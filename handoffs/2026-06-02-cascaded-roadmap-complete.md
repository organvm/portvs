## Key Decisions

| Decision | Rationale |
|----------|-----------|
| PORTVS is a protocol, not a directory | Publish-aggregate-consume; no agent writes directly to shared surface |
| Graph uses phase field as lifting dimension | Unifies 4 registries (atoms, plans, IRF, pipeline) into one lattice |
| Merge rule: incoming wins, not timestamp | Publishing is explicit intent; timestamps are metadata |
| Auto-publish window: 4 hours | Session-scoped, prevents flooding graph with 962 stale plans |
| 2 LSPs at a time max | 16GB Tahoe has logged jetsam kills; incremental only |
| Serena from PyPI, not fork | Fork was stale; canonical source is `serena-agent` package |
| Warp settings excluded from chezmoi | Runtime file written by Warp.app; chezmoi was nuking customizations |

## Risks & Warnings

- **portal-auto-publish dedup is substring-based** — if a plan filename appears in an existing node's content, it's skipped. False negatives possible if two plans have similar names.
- **portal-sync auto-commit depends on git being configured** in the PORTVS repo. If git push fails (auth, network), the sync still succeeds — graph is written locally but not pushed.
- **The graph is NOT a database** — 27 nodes in a flat JSONL file works, but at 10,000+ nodes performance will degrade. Cross that bridge when the migration pass runs.
- **Chezmoi overwrite-all** will still deploy settings.json.tmpl and hooks.json from source — but Warp settings and INDEX.md are now protected. Other runtime files may still be vulnerable.
