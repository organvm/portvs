The unified object is the **Visual Form Canon**. The earlier Visual Media Canon
is a branch of it, not the whole object.

Every leaf reduces to:

```text
source set + visual grammar + runtime target + remix transforms + public/private boundary + promotion target
```

Portvs owns the canonical record while the shape is still unresolved. That
record lives here in the incubator as the lineage receipt, `VISUAL_FORM_CANON.md`,
this unification note, and the existing triptych prototype contracts. Portvs
should not absorb Media Ark's processing job, portfolio's public gateway job, or

## Refraction Apertures

Portvs conductor:

- Holds the canonical object, prompt-lineage synthesis, promotion map, ideal
  form reduction, and refraction rules.
- Starts cross-project visual reviews from the GitHub remote census, not local
  checkout discovery.
- Keeps new work inside `incubator/triptych-video-canon/` until promotion.
- Does not mutate `graph.jsonl` until there is an explicit promotion decision.

Media Ark source-custody aperture:

- Owns library-scale ingestion, canonical media artifacts, metadata sidecars,
  dedupe, indexing, source receipts, and restageable media-processing APIs.
- Becomes the implementation target if the next useful move is reusable
  Photos/Finder/media processing across many visual forms.

Portfolio public gateway:

- Owns public presentation, product framing, product/shop experiments, case
  studies, and commerce handoff.
- Consumes only sanitized public packages, release manifests, copy decks, and
  verified media references.

Organvm / OGOD / art-runtime aperture:

- Owns OGOD pages, Pantheon/chamber worlds, symbolic interfaces, web/3D viewers,
  and artistic runtime surfaces when implementation resumes there.
- Consumes only a clear promotion receipt and does not inherit Portvs private
  prompt excerpts or local source paths.

Exhibit/art aperture:

- Owns gallery, kiosk, digital-frame, screensaver, installation, wallpaper, and
  artwork-specific playback forms when the work is meant to be shown as an
  artwork rather than processed as an archive or sold as a product.
- Consumes public exhibit programs, cue sheets, living-loop contracts, and
  verified package media.

Archive aperture:

- Owns cold preservation, source custody receipts, package snapshots, and
  evidence that originals can be restaged without publishing private paths.

## Rules

- Raw prompt lineage stays private under ignored `work/`.
- Remote repository census stays private under ignored `work/`; tracked notes
  may cite aggregate counts, candidate owners, and decisions.
- Tracked docs may mention counts, clusters, and decisions, but not raw prompt
  bodies, Photos paths, local session paths, or source media filenames.
- Source-library access remains metadata-first and opt-in. Do not mutate the
  Photos library.
- Generated lanes stay ignored: `work/`, `samples/`, `renders/`, `site/`, and
  `packages/`.
- Treat this offload worktree as a Glitche-ready public package plus private
  plans for the other editions unless the older multi-edition state is restored
  or reconciled explicitly.
- Do not touch Limen, `config/_limen`, Media Ark implementation files,
  portfolio implementation files, organvm implementation files, or other
  adjacent repos as part of this incubator pass.

## Promotion Evidence

Promote toward Media Ark when the next durable object is source ingestion,
metadata cataloging, dedupe, canonical media storage, search, or repeatable
processing across many visual projects.

case-study presentation, product/shop framing, a live page, or commerce
integration.

Promote toward organvm / OGOD / an art-runtime repo when the next durable object
is a symbolic world, chamber viewer, web/3D runtime, or revived implementation
of an existing art surface.

Promote toward an exhibit/art repo when the next durable object is a kiosk,
screensaver, wallpaper loop, installation, gallery loop, artwork-specific
renderer, or curated program.

Promote toward a new repo only if the Visual Form Canon becomes a reusable
runtime that is too large or too cross-cutting for Portvs incubation, Media Ark
processing, portfolio presentation, or an existing art repo.

Keep it in Portvs while the core decision is still lineage, ownership,
refraction, ideal-form reduction, or incubation.
