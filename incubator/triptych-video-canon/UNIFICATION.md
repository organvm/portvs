## Canonical Object

The unified object is the **Visual Media Canon**:

- A source-custody layer for Photos, Finder folders, prior films, stills, and
  adjacent visual work.
- A composition layer for triptych/canon timing, panel rearrangement, visual
  sketches, edition maps, and public playback controls.
- A refraction layer that records which surface owns which projection without
  forcing all work into one repo.

Portvs owns the canonical record while the shape is still unresolved. That
record lives here in the incubator as the lineage receipt, this unification
note, and the existing triptych prototype contracts. Portvs should not absorb
Media Ark's processing job or portfolio's public gateway job.

## Refraction Apertures

Portvs conductor:

- Holds the canonical object, prompt-lineage synthesis, promotion map, and
  refraction rules.
- Keeps new work inside `incubator/triptych-video-canon/` until promotion.
- Does not mutate `graph.jsonl` until there is an explicit promotion decision.

Media Ark processing aperture:

- Owns library-scale ingestion, canonical media artifacts, metadata sidecars,
  indexing, and durable media-processing APIs.
- Becomes the implementation target if the next useful move is a reusable
  Photos/Finder media pipeline rather than a single artwork renderer.

Portfolio public gateway:

- Owns public presentation, product framing, product/shop experiments, and
  commerce handoff.
- Consumes only sanitized public packages, release manifests, copy decks, and
  verified media references.

Exhibit/art aperture:

- Owns gallery, kiosk, digital-frame, installation, and artwork-specific
  playback forms when the work is meant to be shown as an artwork rather than
  processed as an archive or sold as a product.
- Consumes public exhibit programs, cue sheets, living-loop contracts, and
  verified package media.

Archive aperture:

- Owns cold preservation, source custody receipts, package snapshots, and
  evidence that originals can be restaged without publishing private paths.

## Rules

- Raw prompt lineage stays private under ignored `work/`.
- Tracked docs may mention counts, clusters, and decisions, but not raw prompt
  bodies, Photos paths, local session paths, or source media filenames.
- Source-library access remains metadata-first and opt-in. Do not mutate the
  Photos library.
- Generated lanes stay ignored: `work/`, `samples/`, `renders/`, `site/`, and
  `packages/`.
- Treat this offload worktree as a Glitche-ready public package plus private
  plans for the other editions unless the older multi-edition state is restored
  or reconciled explicitly.
- Do not touch Limen, `config/_limen`, Media Ark implementation files,
  portfolio implementation files, or other adjacent repos as part of this
  incubator pass.

## Promotion Evidence

Promote toward Media Ark when the next durable object is source ingestion,
metadata cataloging, dedupe, canonical media storage, search, or repeatable
processing across many visual projects.

Promote toward portfolio when the next durable object is public narrative,
case-study presentation, product/shop framing, a live page, or commerce
integration.

Promote toward an exhibit/art repo when the next durable object is a kiosk,
installation, gallery loop, artwork-specific renderer, or curated program.

Promote toward a new repo only if the Visual Media Canon becomes a reusable
runtime that is too large or too cross-cutting for Portvs incubation, Media Ark
processing, or portfolio presentation.

Keep it in Portvs while the core decision is still lineage, ownership,
refraction, or incubation.
